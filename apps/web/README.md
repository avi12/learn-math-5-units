# לוח מתמטיקה — your-site.web.app

לוח כתיבה בעט לטאבלט, שמשתקף בזמן אמת למסך המחשב. הכפתור המרכזי מעתיק את מה שכתבת
כתמונה, כדי להדביק ישירות בשיחה עם קלוד או לשלוח למורה.

**https://your-site.web.app**

## איך משתמשים

1. פותחים את הכתובת במחשב. מופיע קוד QR.
2. סורקים אותו פעם אחת מהטאבלט — שני המכשירים נכנסים לאותו חדר, והחדר נשמר בדפדפן
   של שניהם, כך שבפעמים הבאות פשוט פותחים את הכתובת.
3. כותבים בטאבלט. הכתב מופיע במחשב תוך כדי.
4. **העתק כתמונה** → מדביקים.

הכלים: עט בלחיץ (עובי לפי לחץ העט), ישר, מלבן, מעגל, ארבעה צבעים, ביטול אחרון וניקוי.
דחיית כף יד פעילה: אחרי שהעט נגע במסך, מגע אצבע מתעלם למשך שנייה וחצי.

## שתי דרכים להוציא מכאן תוצאה

**תמונה** — לכתב יד, לסרטוט, לכל מה שהעט טוב בו. קלוד קורא כתב יד מתמטי ישירות מהתמונה.

**LaTeX** — שורת הנוסחה קוראת את הקנבס, ממירה ל-LaTeX, ומריצה שוב בכל פעם שהכתב משתנה
(1.3 שניות אחרי שהעט נעצר, כדי לא לירות בין שתי משיכות). התוצאה נכנסת לעורך
[MathLive](https://mathlive.io) ולא לתיבה קפואה, כי זיהוי אף פעם לא מושלם ולתקן סימן
אחד עדיף על להקליד הכול מחדש.

### מה צריך כדי שהזיהוי יעבוד

**מפתח Anthropic, וזהו.** פותחים את שורת הנוסחה, מדביקים את המפתח בשדה, לוחצים שמור.
הדפדפן קורא ל‑API ישירות — אין שרת, אין פרוקסי, אין שירות נוסף להקים.

זה עובד בזכות הכותרת `anthropic-dangerous-direct-browser-access: true`. בלעדיה CORS
חוסם את הבקשה לפני שהיא יוצאת מהדפדפן; איתה מפתח שגוי מחזיר 401 (שניהם נבדקו).
התיעוד של Anthropic מסמן במפורש **"internal tools… users are trusted"** כמקרה שבו
זה סביר, וזה בדיוק המקרה: כלי אישי, שני המכשירים שלך, חדר עם מזהה שאי אפשר לנחש.

המפתח נשמר ב‑localStorage של הדפדפן הזה. הוא לא בקוד, לא בגיט, ולא נשלח לשום מקום
מלבד `api.anthropic.com`. אם המכשיר משותף או שאתה מעדיף שהמפתח לא יישב עליו —
`worker/ocr.js` הוא פרוקסי Cloudflare מוכן שמחזיק את המפתח בצד השרת, ואז מדביקים
בשדה את כתובת ה‑Worker במקום את המפתח.

**עלות:** בערך ‎$0.002 להמרה, ואותה תמונה לא נשלחת פעמיים. המודל בקבוע `MODEL`
ב‑`src/lib/recognise.ts`; `claude-haiku-4-5` זול פי חמישה.

### למה לא ספרייה חופשית מקומית

- **pix2tex / LaTeX-OCR** (MIT) ו-**TexTeller** אומנו על נוסחאות **מודפסות** —
  im2latex-100k, שנוצר ברינדור XeLaTeX. כתב יד מופיע ברשימת ה-TODO שלהם עצמם:
  *"support handwritten formulae (kinda done)"*.
- מודלי כתב היד (שורת CROHME: CoMER, BTTR, ABM) הם קוד מחקר עם Python, PyTorch ומשקלים.

קוד חופשי מוריד את העלות לבקשה, לא את השרת — ואתר סטטי ב-Hosting לא מריץ Python.

## בדיקת שורת הנוסחה

```
node texcheck.mjs "https://your-site.web.app/?room=<32 תווים>&role=pad" <debug-port>
```

מריץ Chrome עם `--remote-debugging-port`, מקליד באמת בשדה, מכניס שמונה ביטויים ברמת בגרות
(שבר בתוך שורש, אינטגרל מסויים, הגדרת הנגזרת, סכום, אותיות יווניות), ואז **מרנדר כל פלט
ב‑KaTeX** — כי "יצאה מחרוזת" זו לא הוכחה שהיא LaTeX תקין. בנוסף מוודא שהערך האחרון הגיע
ל‑Firestore.

תוצאה אחרונה: 8 מתוך 8 חוזרים זהים לקלט, 0 כשלי פרסור, הקלדה של `x^2` ואז `+1/2` מייצרת
`x^2+rac12`.

### בדיקת הזיהוי מקצה לקצה

```
node directcheck.mjs "https://your-site.web.app/?room=<32 תווים>&role=pad" <debug-port>
```

מדביק מפתח מדומה, פותח את השורה, ומוודא שהדפדפן שולח PNG ישירות ל‑api.anthropic.com.
**`authentication_error` הוא הצלחה** — הוא מוכיח ש‑CORS עבר ורק המפתח פסול.
אחרון: קריאה אחת של 30KB, שורת ההגדרה נעלמת אחרי השמירה.

#### דרך הפרוקסי (אם משתמשים ב‑Worker)

```
cd worker && echo 'ANTHROPIC_API_KEY = "dummy"' > .dev.vars && wrangler dev --local --port 8811
node ocrcheck.mjs "http://localhost:5193/?room=<32 תווים>&role=pad" <debug-port> http://127.0.0.1:8811
```

מצייר קווים, פותח את השורה, ומוודא שלושה דברים: הזיהוי רץ מעצמו בפתיחה, רץ שוב אחרי
שינוי בקנבס, ו"זהה שוב" תמיד פונה לרשת. **401 מ-Anthropic הוא הצלחה בבדיקה הזאת** —
הוא מוכיח שהתמונה הגיעה לנקודת הקצה של המודל ורק המפתח פסול. אחרון: 3 מתוך 3 עוברים,
מטען של 30KB לקריאה.

## פריסה

```
npm run deploy
```

מפרסם דרך Hosting REST API עם טוקן קצר‑מועד מ‑`gcloud auth print-access-token`, כדי לא
לדרוש `firebase login` ולא להשאיר מפתח שירות על הדיסק. אחרי `firebase login` חד‑פעמי אפשר
גם `npm run deploy:cli`.

הסקריפט מתרגם את `firebase.json` לסכמה של ה‑REST API, כך שהקונפיגורציה נשארת במקום אחד
ושתי דרכי הפריסה לא יכולות להיפרד זו מזו.

### סנכרון — ולמה Firestore ולא Realtime Database

- `rooms/{room}/strokes/{id}` — קווים שהושלמו. כתיבה אחת בסיום הקו.
- `rooms/{room}/live/current` — הקו שבאמצע הכתיבה.
- `rooms/{room}/latex/current` — שורת הנוסחה, מסונכרנת גם היא בין המכשירים.

Firestore מחייב לפי כתיבת מסמך, ולכן **יחידת הסנכרון היא קו שהושלם, לא תזוזת עט.**
בכתב יד זה כמעט אותו דבר: ספרה נמשכת כמה מאות מילישניות, אז המסך במחשב מתעדכן
תו־אחר־תו. גרסה קודמת השתמשה ב‑Realtime Database ושידרה כל 60ms — נוח שם, יקר כאן.

קו שרץ ארוך (עקומה גדולה, מעגל) כן משדר תוך כדי, אבל רק אחרי `LIVE_AFTER_MS = 400`
ובקצב `LIVE_EVERY_MS = 250`. כך העלות גדלה רק עבור מה שבאמת צריך תצוגה רציפה:
פסקה של כתב יד עולה כתיבה אחת לקו, בערך 300–800 כתיבות לשעת עבודה, מול מכסה חינמית
של 20,000 ליום.

המחיר של המעבר: חבילת ה‑SDK גדלה מ‑80KB ל‑167KB gzipped.

### אבטחה — במפורש

**אין התחברות.** ה‑API הניהולי של Firebase Auth דורש חשבון חיוב, וזה כלי אישי בתוכנית
החינמית. במקום זה:

- מזהה החדר הוא 128 ביט אקראיים מ‑`crypto.getRandomValues`.
- החוקים (`firestore.rules`) לא נותנים שום הרשאה ל‑`/rooms` עצמו, ולכן אי אפשר לרשום
  את החדרים. נבדק מול ה‑REST API: חדר באורך 32 עובד, חדר קצר נדחה, ומסמך עם `p`
  גדול מ‑40,000 תווים נדחה.
- המזהה לא מתפרסם בשום מקום — הוא עובר בין שני המכשירים שלך בלבד.

זה מספיק לפנקס טיוטות אישי, וזה לא מספיק למשהו רגיש. **לחיזוק:** להפעיל Anonymous
sign‑in בקונסולה של Firebase, ואז להוסיף `auth != null &&` לשני התנאים בקובץ החוקים.


## שתי מלכודות שעלו בבנייה

**כותרת ה‑Cache-Control לא חלה על `/`.** ב‑Firebase Hosting ה‑glob מושווה ל**נתיב
הבקשה**, לא לקובץ שמוגש. `"/index.html"` לכן לא תופס את `/`, דף הכניסה קיבל את ברירת
המחדל של שעה, וה‑CDN הגיש בנייה ישנה. הפתרון: שלושה globs — `/`, `**/index.html`
ו‑`**/*.@(js|css|woff2)`.

**`onSnapshot` בלי קולבק שגיאה בולע כשלים בשקט.** מאזין שמת נראה בדיוק כמו לוח ריק.
עכשיו יש קולבק שגיאה בשני המאזינים, והוא מציג הודעה אדומה בלוח במקום כלום.
